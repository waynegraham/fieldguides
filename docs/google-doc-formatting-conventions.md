# Formatting conventions for authors

Use these conventions when writing a field guide in Google Docs. They help editors preserve your intended structure when the guide is prepared for the website. The site applies its own fonts, colors, spacing, and page layout after import.

## Quick reference

| Content               | Apply in Google Docs                     | Guidance                                            |
| --------------------- | ---------------------------------------- | --------------------------------------------------- |
| Page title            | Do not add it in a section tab           | The tab name supplies the title.                    |
| Main section          | Heading 2                                | Use for the major topics within a tab.              |
| Subsection            | Heading 3                                | Use beneath a Heading 2.                            |
| Paragraph             | Normal text                              | Separate paragraphs with one paragraph break.       |
| Strong emphasis       | Bold                                     | Use for a short term or phrase.                     |
| Light emphasis        | Italic                                   | Use for light emphasis or titles of complete works. |
| Link                  | Insert link                              | Use descriptive link text.                          |
| Steps                 | Numbered list                            | Use only when order matters.                        |
| Related items         | Bulleted list                            | Use when order does not matter.                     |
| Image                 | Insert image, then add alt text          | Alt text is required for informative images.        |
| Structured comparison | Table                                    | Use only for genuinely tabular information.         |
| Pull quote            | Normal text beginning with `Pull quote:` | Keep it to one sentence or a short paragraph.       |

## Paragraphs and fonts

Apply **Normal text** to body paragraphs. Separate paragraphs with a single paragraph break.

Do not choose a font, font size, text color, highlight color, alignment, indentation, or line spacing to control how the published guide will look. The website applies those styles consistently and lets readers adjust text size and line spacing.

Example:

This is a body paragraph. It will use the website's reading font and spacing after publication.

This is a second paragraph. A paragraph break separates it from the first.

## Headings

Apply **Heading 2** to a main section and **Heading 3** to a subsection. Do not add a Heading 1 inside a section tab because the tab name supplies that title.

Keep headings in order. Do not use Heading 3 unless it falls beneath a Heading 2. Do not use bold text as a substitute for a heading.

Example structure:

**[Heading 2] Plan the project**

Introductory paragraph for the section.

**[Heading 3] Define the scope**

Supporting paragraph for the subsection.

## Bold and italic text

Use **bold** for a term or short phrase that needs strong emphasis.

Use _italic_ for light emphasis, titles of complete works, or a word discussed as a word.

Do not underline text for emphasis because underlining is reserved for links on the website. Avoid combining bold, italic, underline, color, or highlighting merely for decoration. Do not emphasize an entire paragraph.

Examples:

- Use **required** when the reader must complete an action.
- Read _The Complete Guide Title_ before beginning.

## Links

Select meaningful words and use **Insert link**. The link text should tell readers where the link leads, even when read out of context.

Acceptable: Read the **CLIR publications catalog**.

Avoid: **Click here** for more information.

Use a complete `https://` address for an external website. Check each link before marking the document ready for import.

## Images and alt text

Every informative image must have alt text:

1. Select the image.
2. Open **Image options**.
3. Open **Alt text**.
4. Add a concise description of the information or purpose conveyed by the image.

Describe what the reader needs to understand, not every visible detail. Avoid beginning with “image of” or “picture of.” Do not repeat a nearby caption word for word.

Example alt text: `Three overlapping circles labeled People, Process, and Technology`

Use empty alt text only when an image is purely decorative and adds no information. Add a caption below an image when readers need a visible credit, source, or explanation. Alt text and captions serve different purposes.

Keep an image inline with the text. Do not use floating images, drawings, text boxes, or tables to position images on the page.

## Bulleted lists

Use a bulleted list when item order does not matter. Introduce the list with a complete sentence. Keep the items grammatically parallel and use punctuation consistently.

Example:

- Name the decision clearly.
- Give the reader enough context.
- Keep related items together.

## Numbered lists

Use a numbered list when sequence or item count matters. Use the Google Docs numbered-list control instead of typing numbers manually.

Example:

1. Define the scope.
2. Assess available capacity.
3. Document the workflow.

Avoid deeply nested lists. If a step needs a long explanation or several substeps, consider giving it a short heading.

## Tables

Use a table for compact, structured comparisons. Give every column a short, descriptive header and keep cell content concise.

Example:

| Component | Use it for                | Avoid it for                |
| --------- | ------------------------- | --------------------------- |
| Table     | Comparing repeated fields | Long narrative explanations |
| List      | Grouping related items    | Multi-column comparisons    |

Do not use a table to create columns, position an image, make a callout box, or otherwise control page layout. Do not nest one table inside another. Editors review every imported table before publication.

## Code, commands, and filenames

The current Google Docs import does not have a dedicated code style. Put a short filename, command, component name, or literal value in a separate, clearly labeled sentence when needed.

Example: Run the following command: `pnpm run build`

For a multi-line code sample, introduce it with a sentence and place it in its own paragraph. Ask an editor to review the result after import. Do not use a one-cell table, custom font, text box, or background color to imitate a code block.

## Pull quotes

Begin the paragraph with `Pull quote:` followed by one memorable sentence or short paragraph. The importer removes the prefix and applies the website's pull-quote component.

Example:

Pull quote: A useful field guide supports action at the point of need.

Do not use a pull quote for routine notes, warnings, section headings, or long quotations from another source.

## Quotations and citations

Put a short quotation in its own paragraph and identify the speaker or source in the surrounding text. Use **Insert → Footnote** for a brief citation or supplementary detail that would interrupt the main text. Place the footnote marker immediately after the relevant text or punctuation.

Example:

As Author Name explains, “A short quotation appears here.”¹

¹ Author Name, _Publication Title_ (Publisher, 2026), 12.

Keep each footnote concise. A footnote can include emphasis and links. Do not use footnotes for essential instructions, headings, images, tables, or long supplementary sections. The importer places each exported footnote definition in the same website section as its reference and reports missing or unused notes for editorial review.

## Formatting that is not currently supported

Do not use the following features in content intended for import:

- Heading 1 inside a section tab
- Custom fonts, font sizes, colors, highlighting, alignment, or spacing
- Underlining for emphasis
- Manually typed superscript note numbers or endnotes; use **Insert → Footnote** instead
- Drawings, diagrams made with the drawing tool, equations, or text boxes
- Multi-column page layouts
- Nested tables or tables used for visual layout
- Floating or text-wrapped images
- Manually typed navigation such as “Next section” or “Back to beginning”
- Comments or unresolved suggestions in a document marked ready for import
- Emoji or color alone to communicate status or meaning

Ask an editor before using a format that is not listed in the quick reference. The editor can recommend an accessible alternative or arrange for a website component.

## Before submitting the document

- Confirm that section tabs have the agreed names and order.
- Confirm that headings use Heading 2 and Heading 3 in sequence.
- Add alt text to every informative image.
- Check that links are descriptive and functional.
- Confirm that tables contain data rather than page layout.
- Remove comments, resolve suggestions, and accept final revisions.
- Remove manual page navigation and decorative formatting.
- Ask an editor to review code samples, citations, and unusual content.
